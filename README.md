# tripcerto.com

This repo is tripcerto.com: the public site for Tripcerto's two products, Engage and Workspace. Five pages (home, Engage, Workspace, Pilot, Trust) and the two legal pages, built with Vite and deployed by Vercel from `main`. It is separate from the product monorepo on purpose: nothing here runs the product.

## What this repo hosts

- The five pages of tripcerto.com: `/`, `/engage`, `/workspace`, `/pilot`, `/trust`. Each is a Vite entry (`vite.config.ts`) with its own head tags; `vercel.json` serves them as clean URLs.
- The privacy notice and terms at `/legal/privacy` and `/legal/terms`: Vite entries that set the documents in `src/content/legal/` inside the site's nav and footer.
- The brand: the marks in `public/brand/`, the Ember tokens in `src/index.css`, and the icon set and the link-preview card in `public/`, both generated by scripts under `scripts/og/`.
- The brand kit, `scripts/brand/tripcerto-brand-kit.html`, generated from the site by `node scripts/brand/build-brand-kit.mjs`.

## What stays in the product monorepo

Engage, Workspace, the admin tools, the edge functions and the database live in a separate private repo. The site imports nothing from it and holds no product code, credentials or customer data; only the two generators under `scripts/` borrow puppeteer from the monorepo's `node_modules`.

## Why the split exists

The public site stays small, safe to share and quick to deploy. A change to the site never waits on a product release, and a product change never touches the site. `tripcerto-public` explains the products; the monorepo runs them.

## The products the site describes

Tripcerto has two products for travel sales. Engage sits on a travel company's website: it answers visitors from the expertise and products the company approves, records what each visitor wants and passes the brief to sales. Workspace sits with the travel expert: it builds the itemised trip from an enquiry, shows what is still missing and resolves prices and availability through the systems the company already runs. The copy for each page is in `src/content/`, one file per page, keyed by the reference in the copy document.

## How the site is put together

- One HTML entry per page, each carrying its own title, description, canonical and social tags; `src/boot.tsx` mounts the page each entry file names.
- Every string on the site is in `src/content/<page>.ts`, keyed by the reference in the copy document. Components carry no copy.
- `src/components/site/` holds the sections; `frames/` under it holds the two product frames, drawn as bars and glyphs rather than text. `src/components/ui/` holds the button and the band shader.
- `src/index.css` holds the Ember tokens (`@theme`), the page surfaces that switch in dark mode, and the utilities.

## Project structure

```
index.html, engage/, workspace/, pilot/, trust/, legal/   # one entry per page, each with its own head tags
src/
  boot.tsx                 # mounts a page
  main.tsx, engage.tsx, workspace.tsx, pilot.tsx, trust.tsx, privacy.tsx, terms.tsx   # entry files
  App.tsx                  # the home page; the others are in pages/
  pages/                   # EngagePage, WorkspacePage, PilotPage, TrustPage, LegalPage
  content/                 # every string on the site, one file per page, keyed by reference; legal/ holds the two documents as HTML
  components/site/         # Nav, Hero, PageHero, Products, Opportunity, Audience, Close, Footer, Section, Rows, Stage, Band, Reveal, Wordmark
  components/site/frames/  # the two product frames: phone, window, the brief card, the story they tell
  components/ui/           # button, gradient-mesh (the band shader)
  lib/                     # links, theme, analytics, utils
  index.css                # Ember tokens (@theme), page surfaces, utilities
  site.test.tsx, test/     # the five checks run over every page, the legal pages' chrome, and the jsdom setup
public/
  brand/                   # the marks: wordmark, monogram, app icon, each in ink and white
  favicon.*, apple-touch-icon.png, icon-*.png, mask-icon.svg, site.webmanifest, og-image.png
scripts/
  og/                      # build-icons.mjs (the icon set); shoot.mjs, card.html and copy.js (the link-preview card)
  brand/                   # build-brand-kit.mjs and render.mjs, the brand kit they write, brand.test.ts
.github/workflows/validate.yml   # the gate every pull request passes
```

## Local development

```bash
npm install
npm run dev        # Vite dev server; /engage and the other clean URLs answer as in production
npm run build      # tsc -b && vite build; emits the five pages and the two legal pages into dist/
npm run lint       # eslint .
npm run test:run   # vitest: the same five checks over every page, plus the brand kit's
npm run audit      # npm audit at every level; zero advisories is the bar
npm run preview    # serve dist/ locally
```

`.github/workflows/validate.yml` runs the type-check, lint, tests, build (and checks every page and both legal pages were emitted) and audit on every pull request. There is no prettier config here and none should be run: the code is single-quoted with no semicolons, and eslint is the only formatting gate. No runtime environment variables are required.

## Deployment

Vercel deploys `main` to tripcerto.com and gives every pull request a preview. `main` takes changes by pull request only: the `validate` check must pass and the branch must be current with `main`.
